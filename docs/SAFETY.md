# Safety boundaries

## Autopilot (0.13)

Autopilot replaces "the owner must have released this helper" with a learned policy, while keeping every mechanical rail. In order: hard rails mark an item **protected** (never burned, never asked); the operator's keeps, a "No" answer or a confident AI keep always win; the operator's "Yes" rules burn; three switchable starter rules burn the obvious; the AI may burn on its own only at ≥ 0.85 confidence for low-risk items (orphaned programs with no listening port, copies not owned by Codex/Claude/Conductor that nothing uses, known junk folders). Everything else becomes a yes/no training question. See [Autopilot](AUTOPILOT.md).

- **Programs.** Only orphan roots under launchd (observed reparenting or a dead job leader; LaunchAgents excluded) are candidates; live descendants are burned with them, deepest first. macOS, app bundles outside automation caches (Playwright/Puppeteer browsers, `node_modules`, temporary folders), harnesses, BurnZombies itself and anything a live chat is working in are protected. SIGTERM only, exact identity (boot, PID, start time, path) re-checked immediately before each signal, exit verified by the monitor. An open socket is a fact the policy sees, not a refusal.
- **Old copies.** Before `git worktree remove --force`, every commit and local change (tracked, untracked and small ignored files outside rebuildable folders) is written to `refs/burnzombies/retired/<id>` in the repository and verified. Browser profiles that test runs leave behind (a Chrome-style profile folder with no file Git tracks) are left out and not counted. A copy with more than 512 MB of other unsaved files is refused, and its receipt names the big folders and files, so the owner can be asked about them. It burns only under a lesson that names each kind of them (code, media, data, archives or other files), which only follows from the owner's Yes to a card that showed that kind. Then the biggest are left out of the restore point and deleted with the copy, as few as it takes for the rest to fit. A folder counts as every kind making up a tenth of it, and as code whenever it holds any. A folder that holds a file Git tracks is never left out whole. A project inside them, ignored or not, still refuses the copy, and the receipt lists what was deleted. Main checkouts, locked copies, in-progress merges/rebases, copies a process uses and dirty or unpushed submodules are refused. The saved/changes facts are recomputed at removal; a change refuses, and a fact the catalog had not checked yet may only turn out safe (saved on a remote, no local changes) or the copy is judged again. Restore recreates the copy at its path and returns local changes as uncommitted.
- **Junk folders.** Only known rebuildable kinds, untracked by git, outside private areas (iCloud Drive, Mail, Messages, Photos, `.ssh`, `.gnupg`, Keychains) and unused by any process. Anything else needs an operator rule and goes to the Trash.
- **Bounds.** At most 50 programs, 20 copies and 20 junk folders burned per sweep; refusals do not count. A refusal stands for the facts and authority it saw for six hours. Refusals and other receipts are each kept up to 500, so a stream of refusals never pushes out restore information and a long burn history never erases a refusal. AI sweeps run headless with six MCP tools and read-only file tools, no shell; every burn is re-authorized natively. They run outside any agent's session: the installer starts BZ with the environment it gets at login, and sweeps and reviews start without a session's IDs, sockets or tokens, even when an agent installed BZ. Failures back off 15 → 120 minutes and never pause the loop.

The sections below describe the evidence-led reviewer and Findings inbox that remain available under Advanced.

## The harness decides; the native app executes narrowly

BurnZombies no longer infers abandonment with fixed age/CPU/ownership heuristics. The user's agent combines live process evidence with ownership evidence across the computer. Cleanup must be within the user's authorization, including an ongoing hygiene request. The model can still misjudge ownership: uncertainty means leave it running, not force a reboot or bulk kill.

The native action surface requires exact process identities, a preview, a rationale and a fresh single-use token. It checks same-user ownership, PID/start time/boot/executable, user protections, current requesting-harness and app ancestry, complete scan coverage and reviewed live children. OS services, main app processes and harness executables are mechanically protected. A passed check is not proof that the task is disposable.

Generic signal previews require positive completion evidence: a released native-bound owner claim, complete passive completion evidence, or an explicitly cleanup-authorized legacy lifetime whose owner has ended. Prose alone cannot authorize an unbound stranger. Active claims, socket consumers and incomplete descriptor visibility block generic signaling. The only generic signal exposed is SIGTERM to each reviewed identity. There is no SIGKILL, process-group kill, reboot, credential change, file sweep, or automatic escalation. A hanging target receives a partial receipt. The app writes intent before signals and never retries a spent preview.

**Residual race:** macOS's public PID-based signal API cannot atomically bind a signal to a recorded start time. The final identity/path/UID check narrows but cannot eliminate an exit/PID-reuse race before `kill`. Polling also cannot guarantee observing short-lived parent edges or a child created between checks. Do not advertise perfect safety.

## Continuous operation and impact

Autopilot's AI sweeps replace scheduled deep hunts ([when they run](AUTOPILOT.md#the-ai-sweep)); the deep-hunt path described here runs only if Autopilot can't start. The resident observer schedules deep hunts independently of chats, every four hours by default. The user can configure that interval or start **Hunt Zombies** manually. Manual requests bypass schedule timing, never Full Disk Access, fresh complete evidence, ownership or cleanup safeguards. One hunt runs at a time. A single selected harness supplies reasoning through focused, bounded and supervised invocations. Account limits, permission errors and uncertain mutation pause review until explicit resume, with no model/provider/account fallback. Proven pre-dispatch transient timeouts receive bounded backoff (at most three attempts for unchanged evidence); unrelated lanes continue and old failed revisions do not consume new evidence. Default setup installs no chat hooks and modifies no persistent harness permissions. Legacy hooks are inert once machine review is configured.

Supported owner operations are distinct from generic SIGTERM: an exact Gradle 8.14.6 or 9.8.2 daemon receives authenticated StopWhenIdle, and local embedded BuildKit uses exact anchored record IDs with engine reference locks. Both use fresh single-use plans, durable prepared receipts and final authorization checks. Unknown versions, remote builders, active/shared cache and incomplete raw filesystem visibility remain protected. A request acknowledgment is never a cleanup receipt.

An idle Gradle preview is revalidated against exact daemon UID, launch identity, distribution fingerprint, last activity and live children. A raced build can finish; verification waits up to 15 minutes for the owner, then watches 120 seconds from observed exit. There is no broad gradle --stop.

 The dedicated reviewer supervisor may terminate its own process group after the grace period to prevent orphaned inference/MCP workers. This ownership boundary does not include user jobs or unrelated harnesses.

The app verifies exact exits and watches for new same-executable children under the same verified parent identity for 120 seconds. Existing siblings and unrelated parents do not count as recurrence. Reparented replacements cannot be reliably attributed. Pending, interrupted, unknown and partial results earn no verified credit. Sleep/restart or large sample gaps invalidate pending continuity. Older-boot identities never authorize a current PID. The app does not need a restart to clean up.

The live hunt scene is presentation, not evidence. Scanner animations do not authorize actions or measure overall completion. A detected candidate is not an eradication; burn celebrations and impact counters follow independently verified process, worktree or disk cleanup receipts.

Memory release uses pre-stop resident footprints; shared pages may overlap. CPU savings accumulate a measured rate during observed awake intervals, capped at 24 observed hours per receipt; historical one-hour credits remain a floor. Sleep and coverage gaps add no credit. Speed compares local command-launch samples; it does not measure remote model latency. Missing data stays unavailable.

## Privacy and storage

Full Disk Access is optional. Without it, process observation, Autopilot, worktree discovery, inspection and cleanup, the storage map and the junk-folder inventory run everywhere except the places macOS protects: Desktop, Documents, Downloads, iCloud Drive and other cloud drives, Mail, Messages, Photos, other apps' data, and removable and network drives. Those places are recognized from the path alone, before anything is read. No listing, metadata read, link resolution or Git command reaches inside one; a checkout whose Git data points into one is skipped; and Git is not asked to list, add, move or remove checkouts of a repository that has a copy in one, because Git looks at every copy. So macOS never shows a folder-access prompt, and a skipped place is reported as skipped, never as empty or missing; a copy there keeps its saved details and decisions until access returns. Autopilot's AI sweeps run without it and skip the same places; the older deep-hunt reviews, lifecycle evidence, owner maintenance and agent requests that inspect or stop programs still require verified access. Verifying access takes an explicit user confirmation and an operational directory check; a saved checkbox alone cannot widen coverage. Access checks are tied to the app's signer (its certificate, or the build itself when it is ad-hoc signed); unknown or revoked access returns BurnZombies to those limits, and directory preflight skips inaccessible subtrees without treating them as empty. Neither mode weakens any ownership, retention or incomplete-visibility guard. See [access setup and signing limitations](INSTALL.md#optional-full-disk-access).

The process observer records executable paths, PID/start/boot, UID, parent PID and resource counters, plus bounded sample history, agent-provided rationale and receipts. It does not store raw command arguments, environment, prompts, browser profiles, terminal text or credentials. The Gradle adapter locally reads narrowly typed launch fields and the exact open owner-log path to identify its distribution and registry. Registry authentication material stays inside the local message adapter and is never emitted. The Docker adapter copies only a local endpoint identity into private temporary configuration, never registry credentials. Storage discovery also records bounded directory metadata. Its explicit evidence tools can return short, filtered source/build/retention excerpts from a measured branch; private state, transcripts, credentials, linked files and online-only content are refused. MCP evidence is visible to the chosen harness and its model provider. See [disk discovery and cleanup](DISK-CLEANUP.md) for the separate file-removal boundary.

The bridge is a private same-user Unix socket and verifies the peer PID for ancestry protection. It is not a security boundary against malicious code already running as that user. No root helper, HTTP listener, telemetry service or separate model account is used.

State directories are 0700, files 0600; bounded reads, no-follow checks, atomic checkpoints and a 24 MiB decompression ceiling constrain storage. The monitor retains at most 4,096 process records, eight samples per record, disappeared records for 24 hours, and 500 receipts for 30 days. Legacy leases grant only their explicit prospective lifetime authority: allowCleanup, ended, not disarmed, exact member and gone owner must all hold alongside current protections. Unknown orphaned processes gain no authority from parent exit. The most recent review output is capped at one MiB in private local storage and may contain process evidence. No private process inventory or Slack feedback belongs in a public issue or test artifact.

## Nonblocking evidence and interrupted operations

The socket listener accepts at most eight concurrent requests. Disk inspection returns cached native measurements and explicit unknown consumer state; one bounded background Mole worker enriches later reviews. Complete consumer inspection remains mandatory for raw removal. Private timing receipts retain only operation names, statuses, durations and response sizes.

Native disk inventories and owner probes run outside the observer actor. Owner actions persist prepared plans before dispatch. Pending or uncertain cache actions reserve their selected IDs and allowance; they are never automatically replayed. Known pre-mutation refusals can be reconsidered only after changed exact resource evidence and the review cooldown. Owner cache capacity is not counted as host disk recovered without separate proof.

## Worktree lifecycle (0.11)

Worktree discovery is read-only. Native adoption of an eligible existing checkout, owner release and human confirmation are separate decisions. Main/bare/default/owner-managed checkouts remain protected. Clean retirement needs complete identity/content/consumer coverage, all claims released or exact human authority, and a caller-bound one-use preview. Explicit dirty retirement additionally needs verified independent recovery. Every destructive step has a durable journal; interrupted work never replays automatically. Recovery is encrypted with this Mac's Keychain key, restored and verified before removal, and retained until explicit purge. Quarantine moves earn no disk credit; changed quarantine content blocks final removal. No branch deletion, double force, gc or broad metadata pruning. See [supported states, recovery dependencies and residual races](WORKTREE-CLEANUP.md).

The native path collector dynamically sizes large file-descriptor tables and resolves updater-moved images through native VM-region metadata and exact denied descriptors through the verified Apple-signed metadata utility, and refuses paths that remain unresolved or incomplete. The fallback checks PID identity before/after, exact descriptor coverage, types, device/inode metadata, bounded output/deadlines and Apple signing. It changes no permissions and never reads file contents. The same strict collector protects disk and worktree removal. Scanner/Git supervisors may tear down only their own newly created process groups; user jobs are outside those groups. Worktree SQLite corruption pauses only worktree management. Claims and recovery operations are separate from the pruned process catalog. Migration clears live legacy action copies before enabling the new executor; old tokens remain valid, while unbound old completion evidence needs renewal.

## Human intent and workflow memory (0.13)

The private SQLite intent ledger gates every native cleanup route. Approval is scoped to exact semantic evidence and consumed at dispatch; Keep crosses action types for the same resource identity. A changed owner, policy, identity or readiness invalidates pending approval. Observation, human intent, technical execution and verified outcome are separate records. A native refusal before dispatch is not an uncertain dispatch. Missing or corrupt journals cannot certify that nothing happened.

New installs receive no implicit cleanup grant. Upgrade migration writes an independent era receipt and captures existing scope; a missing ledger cannot be regenerated as legacy permission from a catalog and config. Recovery does not depend on the intent store: failed recovery feedback independently suspends cleanup until the actual feedback is reconciled. Restoring or reporting needed work pauses its workflow; it does not become positive training.

Workflow rules require explicit scope, cap and expiry. Shadow rules never authorize actions. The first actual action must verify before another proceeds. Replacing a rule does not reset its workflow's daily cap or bypass uncertainty. Forgetting revokes automation and deletes personalization decisions while keeping operation and recovery obligations. The selected model can receive scoped decision history only when enabled; no model fine-tuning or numerical safety probability is claimed.

Exact fixture provenance propagates through native receipts and the intent ledger. Fixtures retain recoverability but are excluded from real impact and normal notifications. Custom state roots and suggestive names alone never mark production work as a test. Compact resolved presentation history after 90 days and delivery diagnostics after 30 days; unresolved authority, Keep, active policy evidence and native recovery bindings remain.
